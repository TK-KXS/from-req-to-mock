# บันทึกการประชุม: ระบบสต็อกสินค้า
**วันที่:** 2 พฤศจิกายน 2026  
**ผู้ให้ข้อมูล:** สมชาย (Ops Manager), กัญญา (หัวหน้าคลัง)  
**ผู้บันทึก:** TK (BA)  

---

## 1. ภาพรวมโปรเจกต์และปัญหาปัจจุบัน
- ยกเลิกการใช้ระบบ Excel เนื่องจากไฟล์เสียหายบ่อย ข้อมูลทับซ้อน และเกิดปัญหาข้อผิดพลาดในการตรวจสอบสต็อก
- พัฒนา Web Application สำหรับใช้งานบนอุปกรณ์พกพา (มือถือ/แท็บเล็ต) เพื่อความสะดวกในการตรวจนับสินค้าภายในคลัง
- ออกแบบส่วนติดต่อผู้ใช้งาน (UI) ให้เรียบง่าย ลดจำนวนขั้นตอนการทำรายการ เพื่อรองรับพนักงานคลัง

---

## 2. ฟังก์ชันการทำงานของระบบ

### การกำหนดสิทธิ์ผู้ใช้งาน (RBAC)
1. **Admin:** สิทธิ์สูงสุดในการดูข้อมูลทั้งหมด ปรับปรุงสต็อก และอนุมัติรายการสินค้าสูญหายหรือส่วนต่าง
2. **Warehouse Staff:** บันทึกรับเข้า-จ่ายออก และบันทึกผลการนับสต็อกประจำวัน
3. **Executive / Auditor:** สิทธิ์สำหรับดูรายงานอย่างเดียว ห้ามแก้ไขข้อมูล

### หน้าแรก (Dashboard)
- แสดงภาพรวมสต็อกสินค้าคงเหลือและสถานะสินค้าใกล้หมด
- ระบบแจ้งเตือน (Safety Stock Alert)
- ช่องค้นหาด่วน (Quick Search) รองรับการค้นหาด้วยรหัส SKU หรือชื่อสินค้า

### ระบบจัดการสต็อก (Core Inventory)
- **จัดการข้อมูลสินค้า:** บันทึกและแก้ไขข้อมูล SKU, ชื่อ, หมวดหมู่, ราคา, จุดเตือนสต็อก และซัพพลายเออร์
- **รับเข้า / จ่ายออก:** บันทึกรายการผ่านการสแกนบาร์โค้ดหรือเลือกรายการ ระบุจำนวน และเลือกประเภทธุรกรรม (ซื้อเข้า, ขายออก, สินค้าเสียหาย, ส่งคืน)
- **การนับสต็อกประจำวัน (Cycle Count):** 
  - รองรับการเริ่มรอบนับตามโซนหรือชั้นวาง
  - เปรียบเทียบยอดนับจริงกับระบบโดยอัตโนมัติ
  - **เงื่อนไขควบคุม:** หากผลต่างเกิน 5% หรือมูลค่าเกิน 1,000 บาท ระบบจะบังคับส่งคำขอให้ Admin ออนุมัติก่อนตัดสต็อกจริง
- **การสแกนบาร์โค้ด:** รองรับการสแกนผ่านกล้องมือถือ/แท็บเล็ต และเครื่องสแกนบาร์โค้ด USB

### รายงาน (Reports)
- รายงานประวัติการเคลื่อนไหวสินค้าเข้า-ออก (รายวัน/รายเดือน)
- รายงานมูลค่าสต็อกรวมในคลัง
- รองรับการส่งออกข้อมูล (Export) เป็นไฟล์ Excel และ CSV

---

## 3. เงื่อนไขทางเทคนิค (Non-Functional Requirements)
- **ประสิทธิภาพ:** การประมวลผลผลลัพธ์จากการสแกนบาร์โค้ดต้องเสร็จสิ้นภายในระยะเวลาไม่เกิน 1 วินาที
- **โครงสร้างพื้นฐาน:** ดำเนินการบน **Huawei Cloud** เท่านั้น
- **การสำรองข้อมูล:** กำหนดรอบการสำรองข้อมูล (Backup) ทุกวัน

---

## 4. ประเด็นที่ต้องติดตาม (Pending Items)
- การเชื่อมต่อระบบภายนอก (ERP / POS): ยังไม่ดำเนินการในเฟสแรก แต่ต้องออกแบบโครงสร้าง API รองรับไว้ล่วงหน้า
- รูปแบบมาตรฐานของป้ายบาร์โค้ดในปัจจุบัน
- ช่องทางการแจ้งเตือนกรณีที่ต้องรอการอนุมัติส่วนต่างสต็อก

---
