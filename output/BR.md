# ระบบสต็อกสินค้า - เอกสารความต้องการทางธุรกิจ (BR)

## 1. ภาพรวม (Overview)

| หัวข้อ | รายละเอียด |
|---|---|
| รหัสเอกสาร | TK-BR-001 |
| เวอร์ชัน | 1.0 |
| วันที่ | 10 พฤศจิกายน 2026 |
| สถานะ | ฉบับสมบูรณ์ (Final) |

ลูกค้าต้องการยกเลิกการใช้ระบบ Excel เนื่องจากไฟล์เสียหายบ่อย ข้อมูลทับซ้อน และเกิดข้อผิดพลาดในการตรวจสอบสต็อก จึงต้องการพัฒนา Web Application สำหรับใช้งานบนอุปกรณ์พกพา (มือถือ/แท็บเล็ต) เพื่อความสะดวกในการตรวจนับสินค้าภายในคลัง พร้อมออกแบบ UI ให้เรียบง่ายและลดจำนวนขั้นตอนการทำรายการสำหรับพนักงานคลัง

## 2. ขอบเขต (Scope)

**อยู่ในขอบเขต**

- Web Application สำหรับใช้งานบนอุปกรณ์พกพา (มือถือ/แท็บเล็ต)
- ระบบจัดการสต็อกหลัก (Core Inventory) การรับเข้า-จ่ายออก และการนับสต็อกประจำวัน
- Dashboard, การแจ้งเตือน Safety Stock, Quick Search และรายงาน
- การสแกนบาร์โค้ดผ่านกล้องและเครื่องสแกน USB
- การกำหนดสิทธิ์ผู้ใช้งาน (RBAC) 3 ระดับ

**อยู่นอกขอบเขต**

- การเชื่อมต่อระบบภายนอก ERP / POS ในเฟสแรก (ต้องออกแบบโครงสร้าง API รองรับไว้ล่วงหน้า)

## 4. ความต้องการ (Requirements)

| รหัส | ความต้องการ | วิธีตรวจสอบ |
|---|---|---|
| REQ-01 | ระบบต้องกำหนดสิทธิ์ผู้ใช้งาน 3 ระดับ (Admin, Warehouse Staff, Executive/Auditor) ตามบทบาท | เข้าสู่ระบบด้วยแต่ละบทบาทแล้วเห็นเมนูตามสิทธิ์ถูกต้อง |
| REQ-02 | Admin ต้องดูข้อมูลทั้งหมด ปรับปรุงสต็อก และอนุมัติรายการสินค้าสูญหายหรือส่วนต่าง | Admin อนุมัติรายการส่วนต่างได้สำเร็จ |
| REQ-03 | Warehouse Staff บันทึกรับเข้า-จ่ายออก และบันทึกผลการนับสต็อกประจำวัน | Staff บันทึกรายการรับเข้าและจ่ายออกได้ |
| REQ-04 | Executive/Auditor ดูรายงานได้อย่างเดียว ห้ามแก้ไขข้อมูล | Auditor เปิดรายงานได้แต่ไม่มีปุ่มแก้ไข |
| REQ-05 | Dashboard แสดงภาพรวมสต็อกคงเหลือและสถานะสินค้าใกล้หมด | Dashboard แสดงยอดคงเหลือและสินค้าใกล้หมดถูกต้อง |
| REQ-06 | ระบบแจ้งเตือน Safety Stock Alert | แจ้งเตือนเมื่อสต็อกต่ำกว่าจุดเตือน |
| REQ-07 | Quick Search ค้นหาด้วยรหัส SKU หรือชื่อสินค้า | ค้นหาด้วย SKU และชื่อสินค้าได้ผลลัพธ์ถูกต้อง |
| REQ-08 | จัดการข้อมูลสินค้า: SKU, ชื่อ, หมวดหมู่, ราคา, จุดเตือนสต็อก และซัพพลายเออร์ | บันทึกและแก้ไขข้อมูลสินค้าครบทุกฟิลด์ได้ |
| REQ-09 | รับเข้า/จ่ายออก ผ่านสแกนบาร์โค้ดหรือเลือกรายการ ระบุจำนวน และเลือกประเภทธุรกรรม (ซื้อเข้า, ขายออก, สินค้าเสียหาย, ส่งคืน) | บันทึกรายการแต่ละประเภทธุรกรรมได้ถูกต้อง |
| REQ-10 | Cycle Count เริ่มรอบนับตามโซนหรือชั้นวาง และเปรียบเทียบยอดนับจริงกับระบบโดยอัตโนมัติ | ระบบแสดงผลต่างระหว่างยอดนับจริงกับยอดในระบบ |
| REQ-11 | หากผลต่างเกิน 5% หรือมูลค่าเกิน 1,000 บาท ระบบบังคับส่งคำขอให้ Admin อนุมัติก่อนตัดสต็อกจริง | รายการที่เกินเงื่อนไขถูกบล็อกรออนุมัติก่อนตัดสต็อก |
| REQ-12 | รองรับการสแกนบาร์โค้ดผ่านกล้องมือถือ/แท็บเล็ต และเครื่องสแกนบาร์โค้ด USB | สแกนผ่านกล้องและเครื่องสแกน USB ได้ทั้งคู่ |
| REQ-13 | รายงานประวัติการเคลื่อนไหวสินค้าเข้า-ออก (รายวัน/รายเดือน) และรายงานมูลค่าสต็อกรวมในคลัง | เรียกดูรายงานแต่ละประเภทได้ถูกต้อง |
| REQ-14 | รองรับการส่งออกข้อมูล (Export) เป็นไฟล์ Excel และ CSV | ไฟล์ที่ Export เปิดได้และข้อมูลครบถ้วน |
| REQ-15 | ประสิทธิภาพ: ผลลัพธ์จากการสแกนบาร์โค้ดเสร็จภายใน 1 วินาที, ทำงานบน Huawei Cloud เท่านั้น, สำรองข้อมูลทุกวัน | ทดสอบเวลาสแกนไม่เกิน 1 วินาที และตรวจสอบ Backup รายวันสำเร็จ |
